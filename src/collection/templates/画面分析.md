# 画面与视频制作拆解

目标是在用户的设备、预算和交付条件下，用尽量少的工序做出观感相近的图片或视频。先锁定决定观感的特征，再核对工具与素材条件，通过小样验证后才铺开。用户未说明条件时，按「个人制作、低成本」试做。优先复用已确认可用的工具。制作软件无法从素材确认时，仍须选定一款适合核心效果的具体软件作为 `[补充建议]` 试做基准，例如基础字卡选剪映专业版或 PowerPoint，确需复杂合成再选 Premiere 或 After Effects。全程沿用所选工具，第一步核对可用性。

正文直接从第一个适用的二级栏目开始，模板总标题由程序添加。外层只保留结论、路线和步骤标题。按下文格式书写的步骤标题会在 Notion 中自动成为折叠块，细节用 `- ` 单层列表写入对应块。视频已知不超过 60 秒且版式单一时，整篇正文含标题控制在 1,500 字符以内。开头合并成片目标、证据范围与共性局限，只写 2–3 个核心特征。脚本与查证各留关键条目，准备和交付可归到对应步骤。同批卡片或同类文字出场合写。复杂素材按实际工序取舍。资料分段时保留素材、时间点和冲突，整合时统一特征与步骤编号。

## 复现目标与优先特征

采用制作术语，按构图与视觉层级、图层与遮罩、发光与描边、采样中可观察的动效线索描述。把 OCR 文字精扫与画面识别分别列证据，OCR 的采样间隔不能当作画面识别间隔。明确区分可见特征与建议采用的合成技法。试做参数标明单位和依据，原片数值、软件入口或版本不确定时标 `[待核实]`。制作参考只引用直接支持本片效果复现的部分，省略与原片效果无关的装饰、增强方案和搜索过程。

- 用一两句话写清成片目标，概括实际获得的静帧、画面识别、OCR、正文、逐字稿或音频分析。正文和逐字稿可以辅助核对 OCR 术语。只有能定位到同一文本且上下文吻合时，才把更正写为已确认。口播与界面文字不一致时保留两种写法，连同低置信识别一起标为 `[待核实]`，说明会影响哪个判断。只有识别描述时，以相对位置、明暗和已描述的纹理为依据，具体色值、锐度等测量结论需要可测的原始素材。
- 给最影响观感的 2–4 项编号「特征 1」「特征 2」。可靠特征更少时按实际数量，缺少可核对特征时先给最小补证要求。每项写「观察及依据 → 可能的表达作用 → 需要保留的视听关系 → 可调整的做法」，并标明是「必须达标」还是「允许调整」。只在口播节拍、工具功能或工序直接影响该特征时引用编号。验收时为每项写通过标准或标出待验证项。
- 按需要观察视觉落点、比例与留白、光色与质感、镜头与字幕层级、声音或叙事配合。依据定位到素材、画面区域、给定时间点或短引文。数值有测量依据时才写成原片测量值。表达对注意力、记忆或留存的影响，缺少观众数据时写成可能的作用。
- 对关键判断使用统一标签。`[素材可核对]` 表示可定位的画面、字幕或音频特征，识别转述要注明来源。`[原作者说明]` 表示可定位且确认归属的作者说法。`[有依据的推测]` 附线索及可能的替代解释。`[补充建议]` 表示为本次复现提出的做法或试做起点。`[待核实]` 写出缺少的依据及其影响。把不同性质的结论分句写。
- 离散采样帧只证明已见状态及其差异。由抽帧不足引起的切点、动画曲线、转场等共同缺口集中在本节标一次 `[待核实]`，后续直接写试做起点。已读取的视频时长和分辨率可直接使用。逐字稿用于核对措辞和顺序。听觉特征需要对应音频分析或可靠标注。

## 口播脚本与表达

有口述或可确认脚本时，按原片顺序挑出真正起作用的环节，例如开场反差、论点推进、举例、转折和收尾。每个节拍写表达目的、原片短例，以及有依据的字幕、画面或听觉配合。直接构成记忆点的视听配合关联到对应特征，纳入后续试做。解释哪些措辞或句式让信息好懂、好记。最后提炼「环节 → 表达目的 → 原创句式占位 → 可配画面」的可迁移骨架。建议配合标为 `[补充建议]`。

视听对位需要共同时间码、可识别的字幕或同一事件等锚点。无锚点时分别列出口播顺序和已见画面，说明要补看哪一段。只有零散字幕时分析可确认的片段。含文字的静帧只分析标题层级、阅读顺序和图文关系。纯视觉无字素材省略本节。

无口播教程可以按 `[画面OCR]` 提取步骤卡、提示条和屏幕说明。分析文字的层级、摆位、阅读顺序和画面配合。教程画面里的软件是作者演示的操作对象，制作整条视频所用的剪辑工具需另找证据。

## 特效做法与查证结果

- 对每个优先特征写「观察到的效果 → 候选原理 → 软件功能 → 入口和适用条件」。同一效果有多个合理原理时，保留会影响选型的差异，说明需要哪条线索区分，并选择一条容易试验的路线。
- 从给定的网页正文节选核对功能、菜单路径和适用条件。来源编号紧贴它支持的做法。软件、模型、版本和参数只有原片或作者证据才归给作者。缺网页时照样给有具体软件名的试做路线。入口未核实或随版本变化时，写功能所在面板或软件内可搜的准确功能名，以及确认办法。只在证据支持时写完整菜单路径。
- 按「能否实现优先特征 → 用户是否具备条件 → 完成与改稿成本」为主路线确定一款操作软件，必要的辅助工具另写分工。具体步骤沿用这款软件。写清开工前提和最大妥协。只有替代路线存在实质差异时才单列，说明切换条件。网页描述了旧版面板时注明版本边界，当前入口缺证就给功能搜索词。缺少实测对照时，用具体差异描述预期。

## 软件、素材与工程准备

- 列出开工需要的工具和素材，把作者证实的工具、从界面推测的工具和建议工具用上面的统一标签标清。缺少字体、纹理、底图、音频或插件时，说明它服务哪个优先特征、可用什么替代、怎样判断替代可接受。
- 把原片已知规格、目标交付规格和试做起点分开。只列会影响制作的画幅、分辨率、帧率、色彩空间、音频或导出条件。跨画幅时先定主体相对位置、字幕安全区和留白关系，具体缩放在目标画布上试验。开工前核对会改变选型的软件可用性、交付规格和第三方素材的用途授权。缺授权时，用自有或已获许可的替代素材做小样。平台规格以可查证的官方要求为准。

## 操作步骤

用 `### 步骤 1｜动词开头的简短动作` 作每步标题，按执行顺序编号，标题不超过 24 字。细节另起行用短列表写。每步交代软件与功能入口、输入、关键动作和可观察的完成状态。会改变结果时才列参数，注明来源、单位或相对比例。只给容易出错或代价高的步骤写「先检查什么 → 怎么调整 → 改完看哪里」。

单一版式短片通常 3–5 步足够。把双栏卡片或同一批文字一起搭建。每步优先保留具体入口、动作和验收，合并重复信息。小样的四项可压缩为一两条。片头已说明的抽帧缺口不在各步骤和交付节重复。

流程按素材裁剪，通常是准备工程与素材、制作并验收最小样片、扩展到剩余部分、导出核对。重复改稿或批量制作才在小样通过后封装母版、预设或可替换图层。画面缺少连续证据时，按需保留的特征选一个可撤销的试做方案，标为 `[补充建议]`。动作可用简单状态变化表达时，按目标决定是否需要过渡。调色、颗粒、暗角、运动模糊或混音调整需对应具体偏差。

把「制作并验收小样」写成正式制作之前的独立折叠步骤，在该步骤内交代以下内容。

- **样片范围**。用尽量少的静帧或短片段覆盖优先特征，逐一标出对照区域或时间范围。关键效果分散时拆成几个小样。两个效果必须配合时，加一个只验证配合关系的短片段。时长随效果调整，核心效果涉及转场时才纳入转场。记录已有的试做时间或轮数上限。用户未给定时，可在完成一轮基线和一次优先修正后评估下一步。
- **通过条件**。按编号写清每项要观察的现象、必须达成的关系和可接受的差异。有量化依据时再给数值。用可比的显示、播放和色彩条件。同画幅可并排比较，跨画幅比较主体相对位置、层级与字幕安全区。有连续画面和同步依据时再检查帧级时序。
- **没通过时**。保留基线样片和工程版本。先核对工程和对照条件，再针对影响最大的偏差写「表现 → 可能原因 → 一个优先调整项 → 复验方法」。优先处理会影响后续效果的变量。确需联动的参数作为一组试验，并回查已通过的特征。达到约定的试做上限仍未达标，或发现工具、授权不可用时，按前面的切换条件换路线。
- **能否铺开**。实际试做后按特征记录「通过」「未通过」或「待验证」。必须达标项全部通过后再扩展制作，允许调整项记录实际差异。试做未通过时，修正或换路线后复验。证据不足时，只推进已能验证且可撤销的部分，先补最可能改变路线的片段、音轨、界面或工程结构。尚未实际制作或对照时，标为「验收计划」。

## 交付与缺口核对

- 列出要交付的成品和必要的可编辑文件。先回放实际导出的文件，按素材核对裁切、字幕可读性、颜色、声音同步和关键效果衔接。只有实际在目标设备或平台预览过时，才标记该环境已核验。发布前确认实际采用的素材许可与最终交付规格。
- 需要移交或反复制作时，附已经验证的工具版本、关键设置、基线工程或母版，以及接手人需另行取得的素材和插件。只保留会改变路线或阻碍交付的 `[待核实]` 项，逐项写明要补什么，以及补齐后要重新判断哪个步骤、参数或交付条件。
