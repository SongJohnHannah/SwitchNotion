# Transcriber 与 NotionSwitch：当前部署和历史对照

更新日期：2026-11-07。NotionSwitch 的 Windows 路径已改为本项目内的算子代码和资源；外部 Transcriber 及旧独立包本次不修改。两者保留相同稳定 Native30 算法的历史，但当前默认资源根和 GPU 队列分开，不能继续描述成跨项目统一调度。

## 当前部署

| 项目 | NotionSwitch 当前项目 | 外部 Transcriber |
| --- | --- | --- |
| 代码入口 | `src/speech/windows-operator/`，应用适配器通过本地工厂加载 | 保留此前独立包客户端，本次未修改 |
| 资源 | `.notion-switch/windows-gpu-operator/`，按项目状态目录解析 | 保留原外部独立包资源根 |
| 自定义 Native 库 | `assets/windows-gpu-native/` 随 Git 保存；完整运行资源按锁导入 | 保留既有 Native13 变体 |
| GPU 调度 | 同一项目资源根内，文件、录音、视频转码共用 lease | 仍使用旧资源根的 lease；与本项目不同 |
| 文件和会话识别 | Large-v3 Turbo、Native CUDA13/sm75、FP16、同步 greedy1；拒绝 CPU 回退 | 历史接入同一稳定算法，当前服务状态未在本次重新探测 |
| 安装与分发 | 代码、自定义 DLL/PYD、方案与资源锁提交 Git；大资源在 Git 忽略目录，Windows 打包按锁纳入 | 本次不重新部署或打包 |

本机资源的一次导入需显式 `--source`，没有 `D:` 盘默认路径；复制完成后，应用运行不依赖来源包。Mac 保留旧 provider、模型选择、安装和 CPU 路线，不加载 Windows GPU 资源。本次只有便携协议/打包测试，没有新增 Mac 硬件验收。

Native30 是 CT2 官方源码针对本机架构的编译与路径封装，稳定变体的 `kernelChanges=[]`。不能把实验分支、私有 FP16 累加或 shortEncoder 描述为默认方案，也没有已验收的 50%/60%提速结论。

2026-11-06 两应用曾共同使用 `D:\迅雷下载\notionSwitch\GPU转写算子`。当时 NotionSwitch 的文件与实时入口、Transcriber 文件入口都经该独立包运行，资源根和 lease 相同。以下是已保存的历史记录，不是本次路径迁移后的重复验收。

历史证据位于该包 `INTEGRATION.md`、`INTEGRATION-VALIDATION.json`、`VALIDATION.json` 及其原始 JSONL/检查点。本次不修改外部包、Transcriber 或这些记录。

当时 Notion PID 48908 的静态状态为 appReady、Turbo/CUDA、资源就绪；Transcriber 的 3066 服务也响应，`resources_ready=true`、`cpu_fallback=false`。这些进程号与服务状态是当时快照，不代表现在仍运行；静态资源描述也不是 GPU probe。

## 识别性能与质量口径

原独立包同一完整采访两轮 **193.326 / 194.858 秒，中位 194.092 秒**，音轨 2806.0373125 秒。这个计时不含前处理、模型载入或排队。上表三个不同应用入口不是同一入口的双轮排名，不能与该基准混算。

以 194.092 秒为基准再下降 50%/60%，目标是 **97.046 / 77.6368 秒**；目前没有同时通过完整内容和稳定性验收的方案达到。历史 B2 中位 104.631 秒存在 24:30–25:00 内容缺失，已撤完整逐字稿资格。

候选须在同一 PCM、相同质量门限下，两次全新目录整片均零 GPU 错误/零恢复，并通过原文审查，才可参加 ≥7% 的比较；门槛为 180.50556 秒。不能以删音频、少生成词句、只挑成功轮或机器参考相同代替完整性审查。机器参考不是人工 WER 真值。

## 更早的接入前审查

首次审查时，Transcriber 历史源码默认 large-v3、beam3、batch8、两个模型实例，并有 CUDA 不可用时 CPU INT8 回退；当时 3066 未响应，不能断言界面实际选择。NotionSwitch 当时也未使用上述 Native30 独立入口。这些事实在 2026-11-06 接入时已改变，不代表本次项目内路径。

旧源码“先由 Torch 统一加载运行库”的注释不能证明实际 DLL 顺序。旧全局 cuDNN 存在多个版本，只提示应审计实际模块路径，不能作为已证明的唯一 GPU 故障根因。旧模型池配置、CPU 回退和吞吐注释不能套用到当前 Windows 算子。

旧外部包的文档备份与 `comparison-doc-update.json` 继续作为历史来源保存。本次文档更新只改变本项目的当前使用说明，不重写旧成绩或声称所有驱动、硬件和语音质量问题已解决。
