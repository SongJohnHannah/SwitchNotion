# 原生公式 AI 预览接口

2026-10-28 增加 `src/native-formula.cjs`，由 `NativeMock` 接管 `runInferenceTranscript` 中的 `config.type = formulas`。与普通侧栏、浮动文字编辑和数据库后台 Autofill 分开处理；Windows 与 Mac 使用同一模块，没有平台路径或系统命令。

## 原生协议依据

当前公开客户端的公式编辑器会发送三类 transcript 步骤：`config`、`agent-record-map`、`user`。配置包含现有公式、编译错误、类型上下文、目标字段和数据库标识；记录图包含字段结构，也可能附带样本行和用户记录。

原生消费者只处理 `generate-formula` 事件；其 `value` 是 JSON **字符串**。已审核的结果形状为 `{type:"formula",formula,format?}`、`{type:"chat",message}`、`{type:"retry"}`。本实现使用前两种：公式预览或说明；不伪造客户端编译/重试成功。

依据：[官方公式编辑器公开脚本](https://app.notion.com/_assets/70785-ca5edbbac4f047aa.js)，SHA-256 `bac5d68b75d615cf6589308a3af5289ec2de175dd70533cd2b9655dc5456f503`；[原生请求封装](https://app.notion.com/_assets/11940-468968c9622585a7.js)。通用语法参照 [Notion 官方公式说明](https://www.notion.com/help/formula-syntax)。官方脚本只用于私有研究和协议核对，不随分发包附带。

## 输入与返回边界

- 只提取当前工作区的数据库字段名称、类型、可选值和关联数据库标识；保留原生类型描述、现有公式和编译错误。排除记录正文、样本行、用户表、权限及原生登录数据。
- 最多 12 个数据库结构、每库 300 字段。问题最多 12,000 字符、现有公式最多 32,000 字符；结构和结果也有总量上限。来源缺失、工作区不符或未知附件步骤在模型前明确失败。
- 模型没有 Notion 工具或代码执行工具，只返回 JSON。无效 JSON、未知字段、空公式、超长结果和供应商异常转为原生说明消息，不将错误文字作为公式应用。
- 公式返回原生编辑器供解析和校验；保存沿用原生用户确认流程。本模块不直接修改字段，不声称任意模型输出均通过 Notion 编译器。
- 原生请求取消或流关闭会中止模型，停止后不返回公式。任务计入 `activeTurns`，避免配置/更新流程将正在生成的公式当成空闲状态。
- 本入口保持临时编辑语义，不新增本地公式历史或缓存，不发送记录正文做模型验收。

## 已验证与仍需验证

`tests/native-formula.test.mjs` 覆盖原生事件编码、结构提取、现有公式和编译错误、关联结构、拒绝/错误、取消及任务状态。Windows 与 Mac 打包测试加载实际复制进包的源文件，验证相同链路。

真实 DeepSeek 使用本次生成的合成字段，分别验证新公式和错误公式修复，2 次请求均返回预期 Formula 2.0 表达式；没有读取真实 Notion 页面或修改远程字段。原生 Windows/Mac 窗口中的展示、编译错误、取消、确认保存与关闭不保存仍需逐项验收；Build with AI 向导和数据库 Autofill 并未因此接入。
