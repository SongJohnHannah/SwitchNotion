# 原生数据库 Autofill 接口

**普通关系字段（2026-10-28）：** 第 1 项追加支持高级模式的普通 `relation`。当前客户端模块 906659 允许人员和未设置 `connectedRelation` 的关系字段，同时明确排除 file、formula、rollup 等计算/特殊字段；文件不再列为待开发的 AI 填充能力。依据[当前客户端执行模块](https://app.notion.com/_assets/57590-3242f968a3670cd0.js)，没有扩展新的产品功能。

关系写回复用现有 NotionRouter 和公开 API `update_database_entry`，由 Notion 维护双向关联及新版边存储。包含关系的记录把本次实际修改的字段合并为一笔 API 更新；不手写反向关系，也不向旧式 block.properties 注入关系。当前工作区连接须对源库、目标库有权限且允许写入；不需要新密钥或其他账号。原生读取仍核对登录用户的所选记录、字段归属及工作流权限，API 另核对数据源、字段 ID/类型、版本、目标记录归属和可用状态。

关系输出为 UUID 数组，遵循单值字段限制；当前每个字段最多 25 个关联，已有目标字段分页不完整时拒绝生成/覆盖。“只填空白”使用 API 实际关系值，兼容原生 block 中没有旧式关系值的情况；条件保留仍适用。人员字段尚未接入，未因关系支持而一并标为完成。

业务值只有独立 API 读回一致才确认；随后仅清理仍属于原批次的原生等待状态。回包丢失会先读回；业务已成功而状态清理失败时，重启只补状态、不重复模型或关系写入。新的字段任务保留；业务结果不明继续阻止重发。复用 API 内核时另修正 IANA 日期的读回比较：本地时间与带偏移的同一时刻可正确核对，不使用电脑默认时区。

**高级 Autofill（2026-10-28）：** 接通单个 Notion 模块的非基础工作流，复用原生 `triggerAgentOverCollection`、任务进度及所选字段写回。按该模块的实际权限读取明确页面/数据库、工作区公开页面及启用的公开网页；Notion 来源还须通过当前工作区 API 连接的授权范围。基础模式仍只使用记录自身内容。

用户已明确允许：在客户端主动运行高级填充时，将该工作流已授权的指定页面、工作区公开页面和启用的公开网页必要正文发送给已配置的 DeepSeek，生成本次所选字段；来源只读，写回仅限所选记录/字段。原生权限结构依据[当前执行模块](https://app.notion.com/_assets/57590-3242f968a3670cd0.js) 的 414741/572473，以及[Notion 权限模块](https://app.notion.com/_assets/77099-fcd336979ae4f4ec.js) 的 853030；不是把客户端模型密钥当成 Notion 内容权限。

高级模式支持指令中的页面提及和 Notion 超链接正文、只读检索及多步提取。来源搜索先按标题检索，再在交给模型前核对页面授权；不扫描尚未授权的正文。`workspacePublic` 仅接纳有原生工作区/公开读取权限的页面，不能据此读取账号个人可见的全部私有页面。受限网页域名同时约束搜索结果、直接读取和每一跳重定向；本地联网开关与 Brave 密钥沿用既有设置。

条件不满足时可保留部分或全部字段，不会将“不操作”误作清空；内部使用 `{"$skip":true}`，无需用户编写该格式。生成过程中只开放读取工具；共用 Agent 的通用报告提示在每轮模型调用前替换为 Autofill 字段 JSON 协议。写前先检查工作流权限/指令，再重新读取所用来源，最后复核所选记录并提交。内容、权限或联网设置变化会拒绝旧结果；重试时失效的未提交草稿会重新生成。未确认的已提交事务仍先核验、防止重复写回。

## 已接入的流程

`triggerLiteAgentAutofill` 和 `triggerAgentOverCollection` 的 `blockFill`、`viewFill` 请求进入本地任务队列。程序使用当前原生登录账号读取工作流、字段结构与明确选择的记录，按指令调用配置的 DeepSeek，校验结果，写入目标字段并读回，然后将任务状态、原生记录更新和分组计数交回客户端。

原生停止按钮使用 `markWorkflowAutomationRunCancelled`；本地任务只停止该记录，其他所选记录仍继续。停止发生在事务提交后时先读回核验，不能承诺撤销已提交的修改。任务计入配置/更新和本地状态接口的忙碌数量。

| 模块 | 职责 |
| --- | --- |
| `native-autofill-store.cjs` | 原生读取、范围/角色/父级/字段归属校验、结果类型与选项检查、受限字段事务、来源复核及读回 |
| `native-autofill-date.cjs` | 日期有效性、范围、时区与偏移量校验，转换原生日期 annotation；提取已有日期供模型使用 |
| `native-autofill-view.cjs` | 捕获范围验证、原生视图归属、有效筛选查询重放、完整结果检查和待写记录范围复核 |
| `native-autofill-executor.cjs` | 生成、批次预检、按记录停止、草稿与写入核验日志、重试及重启恢复 |
| `native-autofill-sources.cjs` | 高级工作流权限解析、受限只读来源工具、条件保留、来源指纹及写前复核 |
| `native-autofill-api.cjs` | 普通关系字段的 API 范围/版本校验、复用字段写入、真实字段值与原生状态恢复 |
| `native-autofill-jobs.cjs` | 任务/分组/run 标识、进度、停止与账号/工作区隔离；成功记录只在字段读回后出现 |
| `compat/autofill.cjs` | 已审核原生生产者的排队与进度桥接；沿用原有计数和停止入口，不使用官方托管任务订阅 |
| `desktop-hook.cjs` / `local-records.cjs` | 原生请求接管、任务状态接口及本地拥有的 run/task_output 记录读取；普通 Notion 读取仍走原路径 |

## 范围与限制

- 工作流须属于当前数据库且只有一个 Notion 模块；目标字段须归该模块所有。基础 `isLite` 使用记录自身资料；高级模式按上面的来源权限执行。支持 text、title、select、multi_select、status、email、url、phone_number、number、checkbox、date，高级模式另支持普通 relation；选项必须已存在。人员尚未接入，文件和计算字段沿用原生禁填规则。其他模块、未知来源权限和云端触发器不在本客户端执行器内模拟。
- 高级模式每行最多 8 轮模型调用和 32 项来源读取；来源过长须分页。网页来源单次最多 8 次搜索、12 个网页，沿用既有正文限制。指令明确引用的页面无法读取时拒绝生成；缺少连接的可选搜索能力会在本轮资料中标明。来源搜索含未能核验的候选时标为不完整，不宣称全量完成。
- 日期模型输出为 `{start,end?,time_zone?}`。日期本身须为真实日历日期；带时间时必须包含偏移量，并提供与之吻合的 IANA 时区。无效闰日、倒序范围、不一致时区、夏令时不存在或重复的本地时刻在提交前拒绝。重复时刻的原生字段没有独立偏移量选择，因此不猜测其含义。
- 日期原生编码依据已审核公共脚本 [22194](https://app.notion.com/_assets/22194-625f5aaea2cefe74.js) 的模块 853300/247438 及 [92196](https://app.notion.com/_assets/92196-7c2cbc12b68c03cb.js) 的模块 797611；使用 `d` annotation，保留 date/daterange/datetime/datetimerange。读回核对完整字段值及 annotation，而非只比较日期占位文字。该版本协议核对不等于当前 Mac 窗口已经验收。
- `blockFill` 处理明确列出的记录；`viewFill` 处理当前视图有效查询的完整结果。最多 200 条、16 个目标字段、4 个并行批次。视图结果不完整、超过上限或来源无法确认时明确失败，不填部分记录，也不扩大成整库。
- 视图查询直接取自发起操作的 `collectionContextStore.remoteRequestStore.state`，包含临时筛选、排序、搜索、时区和关系上下文；同一视图的多个窗口各自保留范围。使用原生 `queryCollection` 从头查询，替换含游标的 reducer，保留其他查询条件；服务端必须明确返回 `hasMore:false`。未知范围字段、多来源或跨工作区视图尚不支持。
- 排队后冻结该批记录及顺序；后来匹配的新记录不加入。每次写回前复核原生视图配置与当前待写记录是否仍符合原条件。已完成的记录因本次填充离开筛选范围时，其他待写记录可继续；待写记录离开范围则拒绝旧结果。当前视图没有加载可见行时仍查询完整范围，空视图不调用模型或提交事务。
- 基础模式读取记录自身字段和正文，不自动打开子页面或链接目标；高级模式增加已授权的指令引用和来源检索。媒体正文未解析时明确标记，不能仅凭说明或 URL 声称已读附件。工作流指令中尚未实现读取的提及不会被静默忽略。
- 生成前检查整个所选批次的来源/权限；先生成和校验全部结果再开始写入。生成后再次检查字段结构、工作流指令及当前记录，变化时拒绝提交旧结果。事务不提供服务端多人编辑锁。
- 只更新目标属性、对应任务状态及必要编辑元数据，保留标题等未选字段、正文、其他记录和其他字段的任务状态；双向关系的反向值由 Notion 按其字段规则维护。取消/失败后仅清理仍与本次原始 creatingTask 一致的状态，不清理新的任务。业务写入不确定时停止后续字段和元数据提交；已独立核验业务结果后可恢复本批状态清理。
- 写回回包丢失时先读回，不重复提交；未确认的写入跨重启继续阻止盲目重试。相同来源的已核验结果及已准备草稿可复用；JSON 字段顺序变化不会触发重复填充。
- 本地任务/run 只能由原账号及工作区读取或停止。本地任务状态文件不保存来源记录正文；含生成结果的核验日志属于私有资料，均不进入 Git 或分发包。
- 核验日志或任务文件损坏时保留原文件并停止该功能写入，返回明确错误；不阻止原有聊天、登录和录音启动，不丢弃核验记录后重新写入。

私有文件：`.notion-switch/autofill-journal.local.json`、`autofill-jobs.local.json`。
